## The workflow changed

**A pull request is the only way into `develop`, and the only way from `develop`
to `main`.** `tools/merge.sh` and `tools/release.sh` merged locally and are
deleted.

```sh
./tools/branch.sh <issue> <slug> --type fix
git push origin fix/<issue>-<slug>
gh pr create --base develop --fill        # CI runs the full set
# merge on GitHub

# to release: bump Cargo.toml, write the CHANGELOG entry
gh pr create --base main --head develop --title "Release 1.1.0"
# merge, then
git checkout main && git pull && ./tag.sh v1.1.0
```

CI runs on pull requests only. `tools/build-host-tests.sh` does everything CI does
plus the performance check and real h2spec/h3spec — neither of which a shared
runner can do — so run it before opening a pull request when a change could touch
either. It needs `M6_BUILD_HOST`; the address is a deployment detail and lives in
the deployment repository, not here.

## Defects found and fixed this session

- **`Request::touch` never reloaded anything on Linux.** It used `utimensat(2)`,
  which reports `IN_ATTRIB`, and the inotify mask did not ask for it. macOS was
  fine because kqueue reports attribute changes, so m6's documented invalidation
  mechanism was broken on the only platform that serves production. Four watcher
  tests passed throughout, because every one of them wrote bytes.
- **A port claim was a file's existence, and the reclaim was a race.** Two
  processes could both judge a marker stale, both unlink, both create, and both
  believe they owned the port. It is an `flock` now, which removes the staleness
  rule rather than repairing it. Six full workspace runs, zero occurrences of
  `Address already in use`, against 2 failures in 5 before.
- **A backend's error headers were discarded** when the edge substituted its own
  error page, so a 429 arrived with no `Retry-After` and a 401 with no
  `WWW-Authenticate`, which RFC 9110 requires.
- **The login throttle counted successes** and never cleared them.
- **Three pre-push hook defects**, all in paths that had never been exercised: a
  ten-minute hook killed every push with SIGPIPE by idling out git's connection; a
  release tag fell through to the work-branch case and was refused, so no release
  could ever have been tagged; and an empty ref list tripped `set -u` on bash 3.2.

## Still open

- **The pre-push hook has no tests.** Three defects in it in one session. Each was
  verified by hand against a real ref line; that belongs in a file.
- **Documentation debts:** 17 modules with no module doc comment, hand-rolled
  calendar arithmetic in `m6-md`, `FrameworkState::build_dict` private so its
  twelve ordered steps are not reusable by a service not using `App`.
- **`docs/PERFORMANCE.md` §4 needs propagating.** `hit_p50_ns` is load-dependent,
  so a fixed baseline band is misleading: it should read "1.7-2.2us at ~40-70
  hits/window" with the window's hit count reported beside the number. A stale
  fixed band misled two separate readings this session.

## Traps

- **A slow pre-push hook breaks pushing.** git opens its connection, runs the
  hook, then sends the pack; a ten-minute hook lets the server close the
  connection and git dies with SIGPIPE and no message. `tag.sh`'s header had
  warned about exactly this and the hook grew slow anyway. Lesson 45.
- **`systemctl is-active` on an absent unit prints "inactive"**, which contains
  the string "active". A grep for it reports every missing service as running.
- **`"${arr[@]}"` on an empty array trips `set -u` on bash 3.2**, still macOS's
  `/bin/bash`. Guard with `${#arr[@]}`.
- **A wait loop with no failure branch is a sleep.** Two were found this session,
  both of which would have reported a symptom far from its cause.
