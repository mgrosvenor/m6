## The workflow changed

**A pull request is the only way into develop, and the only way from develop to
main.** `tools/merge.sh` and `tools/release.sh` are deleted.

```sh
./tools/branch.sh <issue> <slug> --type fix
git push origin fix/<issue>-<slug>
gh pr create --base develop --fill        # CI runs the full set
# merge on GitHub

# to release: bump Cargo.toml, write the CHANGELOG entry
gh pr create --base main --head develop --title "Release 1.1.0"
# merge, then
git checkout main && git pull && ./tag.sh v1.1.0
```

CI runs on pull requests only, not pushes. `tools/build-host-tests.sh` is still
worth running by hand before a PR: it does everything CI does plus the performance
check and real h2spec/h3spec, neither of which a shared runner can do. It needs
`M6_BUILD_HOST` set; the address lives in the site's `docs/OPERATIONS.md`, not in
m6.

## Traps worth knowing

- **A slow pre-push hook breaks pushing.** git opens its connection, runs the hook,
  then sends the pack; a ten-minute hook lets the server close the connection and
  git dies with SIGPIPE and no message. `tag.sh`'s header had warned about this and
  the hook grew slow anyway. Lesson 45.
- **The HTML minifier strips attribute quotes.** Grepping for `loading="lazy"`
  finds nothing; it emits `loading=lazy`. This made a working page look broken and
  then a fixed page look unfixed.
- **The edge cache hides a dead backend for up to a day.** `s-maxage=86400` means
  an asset keeps returning 200 with a rising `Age` after m6-file has stopped being
  able to produce it. Always cache-bust when checking whether a backend serves.
- **Read the live system, not the notes.** I gave a stale job list twice: SPF,
  DMARC and CAA were already done, and `185.19.40.146` had been blocked since
  2026-09-12. The handover's own standing warning covers this.
- **`systemctl is-active` on an absent unit returns "inactive"**, which contains
  the string "active". A grep for it reports every missing service as running.
